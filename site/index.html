Reproducible agent stacks.

An open specification for agent components on disk: the harness, its plugins, and the runtimes they depend on, as a single unit that runs the same way on every machine.

Why Agent Stacks?

An agent is not one program. It is a harness, a set of skills, some MCP servers, a handful of prompts and settings, and implied dependencies. Today those are ad-hoc. "The same agent" could be something different on every machine.

We believe agents should be:

  • Inspectable. Agent parts should be easy to identify.
  • Composable. Agent parts should be easy to change.
  • Reproducible. Agents should run the same on every machine.

A stack on disk

A plugin is a directory laid out as Agent Plugins. A stack installs its plugins under share/agent-plugins/, one directory each, and provides one launcher script at bin/<stack-name>.

agent-stack-my-claude/
├── bin/
│   └── my-claude                # the launcher
└── share/
    └── agent-plugins/
        └── caveman/             # unchanged from the plugin package
            ├── plugin.json
            ├── skills/
            └── bin/             # pinned interpreters the skills run on

See the specification. A Nix build, a Debian package, a Homebrew formula, or a tarball unpacked into /usr/local can all satisfy the specification. Any conforming harness reads the same tree.

A meta specification

Agent Stacks are deliberately minimal interpretations of existing specifications. Every must a builder or a client has to satisfy already comes from one of three specifications.

A reference implementation

agent-pkgs is a Nix package set implementing the layout: skills and MCP server configurations packaged as reproducible, closure-complete packages and composed into stacks. It builds with plain Nix.

nix build github:agent-stacks/agent-pkgs#agent-plugin-caveman

An organization can fork it as an internal plugin marketplace: keep the library functions, replace the package set with your own, and ordinary CI builds every package on every pull request. Nix is the first implementation. We invite additional implementations.

Open development

Agent Stacks is developed in public. Flox is the initial sponsor and wrote the first implementation, and we are looking for contributors and collaborators. We are not attached to any particular technology. The specification is a layout on disk; Nix is just one way to produce it.

If you are packaging agent tooling already, or you maintain a harness that has to load components, we are open to collaborating.
